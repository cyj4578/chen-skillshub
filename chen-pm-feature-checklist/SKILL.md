# chen-pm-feature-checklist — 通用功能清单

## 技能定位

产品经理需求分析阶段第三步。将需求描述转化为可执行的功能清单，按角色端、优先级分级，明确"做什么"和"不做什么"。

## 优先级定义

采用 chen-prd-skills 的 4 级优先级：

| 级别 | 含义 | 标准 |
|------|------|------|
| **P0** | 必须做 | 缺则产品不可用，MVP 必须包含 |
| **P1** | 应该做 | 重要但非阻塞，V1.0 尽量包含 |
| **P2** | 可以做 | 锦上添花，V1.1+ 迭代 |
| **P3** | 明确不做 | 防止需求蔓延，明确排除并说明理由 |

## 输入要求

| 参数 | 必填 | 说明 |
|------|------|------|
| 需求描述 | 是 | 完整的需求背景和功能描述 |
| 限制条件 | 否 | 明确的功能限制（如不做什么、不需要什么） |

## 输出结构

### 模块 1：用户端功能

按功能域分组：

```
功能域名称
├── 功能点 1 [P0/P1/P2] — 一句话描述
├── 功能点 2 [P0/P1/P2] — 一句话描述
└── ...
```

### 模块 2：管理端功能

同用户端结构，按功能域分组。

### 模块 3：明确不做清单（P3）

```
不做项 1 — 理由
不做项 2 — 理由
...
```

### 模块 4：优先级统计

| 优先级 | 数量 | 占比 |
|--------|------|------|
| P0 | n | % |
| P1 | n | % |
| P2 | n | % |
| P3 | n | % |

## 执行流程

```
Step 1: 解析需求描述，识别用户角色和业务场景
Step 2: 按角色端枚举功能点
Step 3: 每个功能点评级（P0-P3）
Step 4: 根据限制条件补充 P3 明确不做清单
Step 5: 输出结构化清单 + 统计
```

## 案例经验（来自 4 个实战项目）

- 直播系统：管理后台 30+ 项 + 小程序 14 项，明确不做推流 SDK、连麦功能
- 签到功能：小程序 20 项 + 后台 18 项（22 P0 + 12 P1 + 4 P2），P3 含社交分享/排行榜
- 账号注销：小程序/公众号/管理后台三端共 50 项（30 P0 + 16 P1 + 4 P2）
- 山姆代购：用户端 16 项 + 商家端 18 项共 34 项（22 P0 + 9 P1 + 3 P2），P3 含库存管理/SKU/网页后台/优惠券/会员等级等 10 项
