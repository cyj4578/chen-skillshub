# 技术实现模块

## 模块定位

pm-agent 子模块。可独立调用，也可被编排引擎串联。将设计文档转化为可交付开发的完整技术方案。

## 独立调用

```
@skill:pm-agent 帮我出技术方案，架构和UI原型如下：XX
```

或被引擎在 DAG Step 6 自动调用（传入架构设计 + UI 原型）。

## 默认技术栈

| 层级 | 技术 | 说明 |
|------|------|------|
| 后端框架 | Node.js (Express/Koa) | 默认，可替换 |
| 数据库 | MySQL 8.0+ | 核心业务数据 |
| 缓存 | Redis 7.0+ | 热数据/会话/队列 |
| 文件存储 | 云OSS/本地 | 按需选择 |
| 容器化 | Docker + Docker Compose | 标准化部署 |
| 前端框架 | 微信原生/React/Vue | 按端类型选择 |

## 输入要求

| 参数 | 必填 | 说明 |
|------|------|------|
| 架构设计 | 是 | 来自系统架构模块的输出 |
| UI原型 | 是 | 来自 UI 原型模块的输出 |
| 技术约束 | 否 | 必须使用或不能使用的技术 |

## 输出结构（5 模块）

### 模块 1：技术选型总览

- 前端（框架/UI库/状态管理/构建工具）
- 后端（语言/框架/ORM）
- 数据库（MySQL/Redis/其他）
- 第三方服务（支付/短信/地图/推送/云服务）
- 运维（Docker/CI/CD/监控/日志）

### 模块 2：核心代码示例

每个关键模块提供示例代码：
- 项目结构
- 数据库连接配置
- 核心业务逻辑（服务层）
- API 路由定义
- 中间件（认证/权限/日志）

语言默认 Node.js/TypeScript，可替换。

### 模块 3：部署方案

- Docker Compose 编排文件
- 环境变量配置
- 数据初始化脚本
- 健康检查配置

## 执行步骤

```
1. 分析架构设计中的技术依赖
2. 确定技术选型（优先默认技术栈）
3. 编写核心代码示例
4. 编写 Docker Compose 部署配置
5. 估算成本
6. 输出风险和建议
```

## 实战经验

- 直播系统：视频号直播 API 接入代码 + 微信支付 + 5 表 DDL + Docker Compose
- 签到功能：Redis Bitmap 签到实现（setbit/getbit/bitcount）+ 加权随机抽奖算法（Alias Method）+ 成本对比（Redis 4.5GB vs MySQL 900GB）
- 账号注销：UnionID 多端同步 + Bull 冷静期延迟任务队列 + 数据分级删除（匿名化/删除/脱敏保留）+ 审计日志
