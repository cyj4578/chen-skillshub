# 竞品分析模块

## 模块定位

pm-agent 子模块。可独立调用，也可被编排引擎串联。深入分析竞品全流程、定价、合规和差异化空间。

## 独立调用

```
@skill:pm-agent 帮我做竞品分析，行业是XX，需求是XX
```

或被引擎在 DAG Step 2 自动调用（传入需求上下文 + 市场调研结果）。

## 输入要求

| 参数 | 必填 | 说明 |
|------|------|------|
| 需求背景 | 是 | 一句话描述要做什么产品/功能 |
| 目标行业 | 是 | 所属行业 |
| 竞品范围 | 否 | 竞品名称列表（不填则自动搜索识别） |

## 输出结构（4 模块）

### 模块 1：竞品矩阵

横向对比表（至少 3 家竞品 + 本方案）：

| 维度 | 竞品A | 竞品B | 竞品C | 本方案 |
|------|-------|-------|-------|--------|
| 目标用户 | | | | |
| 核心卖点 | | | | |
| 定价模式 | | | | |
| 关键功能 | | | | |
| 技术方案 | | | | |
| 市场覆盖 | | | | |
| 优势 | | | | |
| 劣势 | | | | |

### 模块 2：全流程对比

按用户旅程拆解各竞品的完整流程：
- 获客/注册 → 核心操作流 → 支付/交易 → 售后/服务 → 留存/复购

每个环节标注竞品的关键差异点。

### 模块 3：合规分析

按需覆盖：
- 通用合规（个人信息保护法、消费者权益保护法）
- 行业专项合规（如医疗健康的《医疗机构管理条例》、食品的《食品安全法》）
- 平台规则合规（如微信小程序运营规范、微信支付合规要求）
- 行政监管风险（如医美直播曾被叫停）

输出合规自查清单（Checklist 格式）。

### 模块 4：差异化策略

- 竞品未满足的用户需求（痛点机会）
- 本方案的差异化定位建议
- 可实现的独特功能或体验
- 不可复制的核心壁垒（如供应链、独家资源）

## 执行步骤

```
1. WebSearch 检索各竞品的核心模式、定价、功能
2. WebSearch 检索目标行业的合规要求和监管动态
3. WebFetch 补充竞品官方页面/深度分析
4. 按 4 模块结构整理输出
5. 标注所有引用来源（URL + 年份），确认均在近 2 年内
```

## 引用规范

- **仅引用最近 2 年资料**（如当前 2026 年，只用 2024-2026 年）
- 标注来源 URL 和具体日期/年份
- 合规条款需注明具体法规名称和条款号

## 实战经验

- 医美口腔直播：发现 2024 年医美直播被喊停的合规风险，分析合规转型方案
- 签到+抽奖：分析不确定奖励机制对留存的提升（+116%），奖品价格 ≤5 万合规红线
- 医疗健康注销：分析敏感医疗数据处理要求、个人信息保护法合规清单、多端注销同步
- 山姆代购：分析原始微信代购 vs 美团代购 vs 小程序的定价/信任/效率三维对比
