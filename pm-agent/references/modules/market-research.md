# 市场调研模块

## 模块定位

pm-agent 子模块。可独立调用，也可被编排引擎串联。将任意需求背景转化为结构化的市场调研报告。

## 独立调用

```
@skill:pm-agent 帮我做市场调研，行业是XX，需求是XX
```

或被引擎在 DAG Step 1 自动调用（传入需求上下文）。

## 输入要求

| 参数 | 必填 | 说明 |
|------|------|------|
| 需求背景 | 是 | 一句话描述要做什么产品/功能 |
| 目标行业 | 是 | 所属行业（如电商、医疗、教育等） |
| 调研深度 | 否 | `basic`（基础）/ `standard`（标准，默认）/ `deep`（深入） |

## 输出结构（5 模块）

### 模块 1：市场概况

- 市场规模（货币化/用户量级，标注数据来源年份）
- 增长趋势（同比/复合增长率）
- 关键驱动因素（政策、技术、消费习惯等）
- 主要参与者分布

### 模块 2：产品类型分类

按形态/模式/规模等维度分类（至少 3-5 种），每类包含：
- 定义与特征
- 代表产品
- 适用场景
- 优劣势

### 模块 3：核心功能全景

按模块维度（用户端/管理端/运营端）罗列行业标准功能：
- 必选功能（行业标配，缺则不可用）
- 增值功能（差异化竞争力）
- 未来趋势功能（技术驱动的新功能）

### 模块 4：典型案例（至少 3 家）

每案例包含：
- 产品名称与所属公司
- 核心定位与目标用户
- 关键功能特色
- 商业模式/盈利方式
- 市场表现（用户量、GMV 等，标注数据来源）

### 模块 5：技术方案对比

| 维度 | 方案A | 方案B | 方案C |
|------|-------|-------|-------|
| 架构模式 | SaaS / 私有化 / 混合 |
| 核心技术栈 |
| 扩展性评估 |
| 成本估算 |
| 适用场景匹配 |

## 执行步骤

```
1. WebSearch 检索行业概况、市场规模、主要玩家
2. WebSearch 检索核心功能、典型案例详情
3. WebFetch 补充关键案例的官方/深度分析页面
4. 按 5 模块结构整理输出
5. 标注所有引用的数据来源（URL + 年份）
```

## 引用规范

- 所有数据标注来源 URL 和发布/更新年份
- 行业报告优先引用官方/知名机构（艾瑞、QuestMobile、CNNIC 等）
- 竞品功能描述优先引用官方文档或权威评测

## 实战经验

- 直播系统：覆盖视频号/抖音/淘宝/有赞/微盟 5 类，产出 5 大核心功能模块 + 3 家案例
- 签到系统：覆盖连续/累计/阶梯/任务/社交 5 类签到，Redis Bitmap vs MySQL 技术对比
- 注销系统：覆盖即时/冷静期/人工审核 3 种类型，微信/支付宝/抖音/淘宝 4 家对比
- 山姆代购：覆盖 C2C/平台/私域/SaaS/社区团购 5 类，4 种定价模式
