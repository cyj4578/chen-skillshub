# 系统架构模块

## 模块定位

pm-agent 子模块。可独立调用，也可被编排引擎串联。将功能清单转化为可交付给开发团队的系统设计文档。

## 独立调用

```
@skill:pm-agent 帮我设计系统架构，功能清单如下：XX
```

或被引擎在 DAG Step 4 自动调用（传入功能清单 + PRD + TE 审查结果）。

## 输入要求

| 参数 | 必填 | 说明 |
|------|------|------|
| 功能清单 | 是 | 来自功能清单模块的输出 |
| 需求背景 | 是 | 业务场景和限制条件 |
| 已有系统 | 否 | 需对接的现有系统描述 |

## 输出结构（5 模块）

### 模块 1：系统分层架构

```
┌─────────────────────────────────────┐
│          用户端/客户端层              │
├─────────────────────────────────────┤
│          接入层 / API Gateway        │
├─────────────────────────────────────┤
│          业务逻辑层                   │
│   ┌─────┐ ┌─────┐ ┌─────┐          │
│   │模块A│ │模块B│ │模块C│          │
│   └─────┘ └─────┘ └─────┘          │
├─────────────────────────────────────┤
│          数据层                      │
│   ┌─────┐ ┌─────┐ ┌─────┐          │
│   │MySQL│ │Redis│ │ OSS │          │
│   └─────┘ └─────┘ └─────┘          │
└─────────────────────────────────────┘
```

### 模块 2：数据流转图（至少 3 张）

每张流程图包含：
- 参与者（用户/系统/外部服务）
- 数据流转方向
- 关键校验节点
- 异常处理分支

典型流程图清单：
1. 核心业务流程（端到端主流程）
2. 条件校验流程（状态/权限/数据完整性）
3. 数据删除/归档流程（生命周期管理）
4. 支付/交易流程（如有）
5. 异步任务流程（定时任务/消息队列）

### 模块 3：数据表设计（DDL）

每张表包含：
- 表名与用途说明
- 字段定义（名称/类型/约束/默认值/注释）
- 索引设计
- 关联关系说明

### 模块 4：API 清单

按业务模块分组，每个 API 包含：
- 方法 + 路径
- 功能说明
- 请求参数（必填/可选）
- 响应结构
- 错误码

### 模块 5：状态机（核心实体）

用文本或 Mermaid 描述关键实体的状态流转：

```
待付款 → 已支付 → 处理中 → 已完成
                 → 已取消
                 → 已退款
```

## 执行步骤

```
1. 分析功能清单，提取核心实体和业务模块
2. 设计分层架构
3. 绘制数据流转图（至少 3 张）
4. 设计数据表 DDL（含索引和关联）
5. 编写 API 清单
6. 定义核心实体的状态机
```

## 实战经验

- 直播系统：分层架构（小程序+视频号SDK+管理后台）、5 张数据流转图、6 表 DDL、18 API
- 签到功能：Redis Bitmap + MySQL 双层存储、5 表 DDL、16 API、签到/抽奖双状态机
- 账号注销：UnionID 多端同步架构、Bull 延迟任务冷静期、4 表 DDL、16 API、注销状态机
- 山姆代购：单小程序双角色架构、无库存简化设计、5 表 DDL、20 API、订单 5 状态机
