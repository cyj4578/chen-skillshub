# TE 逻辑审查模块

## 模块定位

pm-agent 子模块。可独立调用，也可被编排引擎串联。专门检测 PRD 文档中的逻辑漏洞、需求完整性问题和可测试性问题。

## 独立调用

```
@skill:pm-agent 帮我审查这份PRD：[粘贴PRD内容]
```

或被引擎在 DAG Step 3-TE 自动调用（传入 PRD 文档全文）。

## 审查维度（5 大维度 33 项检查）

| 维度 | 说明 | 检查要点数 |
|------|------|-----------|
| 结构完整性 | 文档章节是否齐全 | 10 项 |
| 逻辑一致性 | 目标-需求-指标链条是否对齐 | 8 项 |
| 需求完整性 | 用户故事与功能需求覆盖度 | 6 项 |
| 可测试性 | 验收标准是否可验证 | 5 项 |
| 风险完整性 | 依赖与风险是否识别 | 4 项 |

## 漏洞等级定义

| 等级 | 标识 | 定义 | 影响 |
|------|------|------|------|
| 严重 | 🔴 P0 | 导致需求无法执行或上线后产生重大问题 | 必须修复 |
| 重要 | 🟠 P1 | 影响开发效率或上线质量 | 强烈建议修复 |
| 一般 | 🟡 P2 | 潜在风险或可优化点 | 建议修复 |
| 提示 | 🔵 P3 | 改进建议 | 可选修复 |

## 审查流程

### Phase 1：结构扫描

检查文档是否包含完整的 10 个核心章节：

```
□ 问题陈述
□ 目标
□ 非目标
□ 用户故事
□ 需求详细说明（FR + NFR）
□ 成功指标
□ 开放问题
□ 时间计划
□ 依赖与风险
□ 附录（可选）
```

### Phase 2：逻辑链验证

验证链条一致性：

```
用户故事（US） → 功能需求（FR） → 验收标准 → 成功指标（G）
     ↓                ↓
  优先级          优先级
```

### Phase 3：漏洞检测

执行 33 项系统性检查（详见 `references/te-templates/PRD审查清单.md`）。

### Phase 4：报告生成

输出结构化审查报告。
